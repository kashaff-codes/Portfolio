Supabase · PostgREST · GoTrue
Supabase Lite conformance kit

A differential test kit: the same 81 supabase-js calls go to real Supabase (Postgres) and to Supabase Lite (SQLite), and every difference is classified by how much it would hurt an app — silent wrong data first. 48 failing cases trace to 22 root causes, each linked to the PostgREST (Haskell) or GoTrue (Go) code that defines the correct behaviour. Runs in GitHub Actions and republishes the report on every push.

Then I fixed two of them upstream: case-sensitive like and Postgres NULL ordering, with 13 new tests. Pointed at the fix, the kit went from 33 to 36 passing cases and 15 to 12 silent wrong-data findings — and nothing else moved.

TypeScript supabase-js PostgreSQL SQLite Haskell · Go (source) GitHub Actions

Supabase · Supavisor · PostgreSQL
supabase/supavisor #1051

A transaction-pooler bug where SERIALIZABLE transactions report success and silently discard their writes. I reproduced it on a fresh project, and a Supabase engineer routed the issue to the pooler repository within hours.

Then I narrowed the trigger — away from my own first hypothesis. It is not SSI timing; it is client-side prepared statements. 10 of 16 runs failed with prepare enabled, 0 of 16 with it disabled, and the surplus “successful” commits exactly accounted for the lost rows. Added a psycopg2 control, published a workaround, and opened a PR with the scripts — including the probe that failed, because its null result bounds how narrow the timing window is.

PostgreSQL Supavisor postgres.js psycopg2 SSI

Publication
Auditing my own pipeline
Preprint · Sole author · Zenodo · Sep 2026
A Known-Answer Audit for Deployed Measurement Systems: Procedure and a Case Study

Ranking systems for online community health ship without any mechanism to detect that their ordering is wrong. This paper describes a lightweight known-answer audit procedure for such systems and reports what it found when applied to one deployed pipeline — my own (APOLLO-M): planted ground truth, adversarial cases, per-step metrics instead of one end-to-end number, and a record of where the pipeline was confidently wrong.
